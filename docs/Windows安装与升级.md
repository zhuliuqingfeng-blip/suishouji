# Windows 安装版与升级维护

安装版从 1.8.0 开始提供，继续使用 Electron、React、TypeScript 和现有 SQLite 数据格式。安装器使用现有 electron-builder 的 NSIS 目标，无新增运行时依赖。

## 固定标识与目录

- App ID：`local.suishouji.desktop`。
- NSIS GUID：`42be8a92-8942-4f4c-9e2c-90bd703acc4c`。后续版本必须保持不变。
- 安装范围：当前用户，不要求提升管理员权限；默认使用 Windows 的当前用户 Programs 目录，后续从同一注册项读取安装位置。
- 安装版资料：`%LOCALAPPDATA%\随手记`，无版本后缀。程序安装目录中不包含用户数据库。
- Portable 资料：可执行程序旁的`我的数据`，运行环境、实例锁及数据均与安装版独立。
- 数据库仍为版本 3，正文、附件相对路径、公农历日子及提醒状态的数据格式不变。布局、排序及上次记录继续使用原有 Local Storage，窗口信息仍在`.运行缓存/window-state.json`。

打包元数据 `distribution` 明确区分安装版与 Portable，不根据程序所在位置猜测版本。只有 `NOTES_TEST_MODE=1` 且指定测试目录时才走隔离存储；正式安装验收还使用独立的 LOCALAPPDATA，实际运行安装版代码路径。

## 安装、升级及卸载

NSIS 提供中文引导、可浏览选择的安装目录、可选桌面快捷方式、开始菜单入口、完成后可选运行和正常卸载。升级默认沿用注册的原安装位置；用户也可在向导中选择另一个空的专用目录，安装器正常移除旧程序并更新快捷方式，个人资料路径不变。直接运行新版安装器即可，不要求先卸载。

1.8.1通过原生MUI目录页使用用户界面中显示的准确路径，避免上游模板在安装开始后追加隐藏子目录。安装开始前检查目标，拒绝个人资料及其父子目录、磁盘根目录、链接目录、含旧Portable资料的目录和非本软件所有的非空目录；提前测试写权限，检查失败不移除旧程序。安装目录内的标识文件只用于识别软件文件夹，不记录个人内容。

安装器覆盖默认的进程结束逻辑：只对安装目录中正在运行的这一份程序调用正常关闭，等待最多25秒。不会使用 taskkill 或强制结束记录进程；保存或备份未完成时，以非零退出码停止升级。Portable 不会因此被关闭。

程序与资料分离，安装器不写入或清除个人资料。`deleteAppDataOnUninstall=false`，未提供删除资料选项；卸载后重新安装仍读取相同目录。升级第一轮启动会在打开 Store 前创建并校验旧数据库的完整 ZIP，成功读取后记录程序版本；升级前备份和每日七份备份分开保存。

Portable 的桌面创建脚本使用“随手记（免安装版）”，窗口标题和资料设置也标明免安装版，避免与安装版入口混淆。两个版本的后续编辑各自独立，不提供隐式同步。

安装位置验收：构建后运行`node scripts/package-installer.mjs --location-qa --previous`和`node scripts/package-installer.mjs --location-qa`，再执行`npm run test:installer-location`。使用独立NSIS GUID和快捷方式，不卸载或覆盖正式安装；测试中文及空格目录、旧位置升级、运行中换位置、目录保护、卸载重装和资料保留。

## 旧版迁移

首次安装提供“从免安装版导入”和“直接开始”；数据与设置中保留导入入口。用户明确选择原软件文件夹或“我的数据”，不搜索或猜测磁盘路径。当前安装版含手记、回收站、附件或重要日子时拒绝覆盖，用户可另外使用已有的完整备份恢复能力。

导入在退出并重新启动后、创建编辑窗口之前执行：

1. 验证源目录结构、SQLite、版本及源程序退出情况，拒绝重叠目录、链接、缺失附件和未完成的旧版恢复。
2. 复制原始资料并逐文件校验；保留数据库、附件、备份、Local Storage 和窗口设置，不复制 GPU 缓存及进程锁。复制前后再次检查源文件变化。
3. 创建、校验完整 ZIP；在暂存副本中验证数据库，不修改旧版原件。
4. 使用磁盘日志逐项发布资料，保留目标原件。中断后启动按日志恢复；提交后保留新资料，不重复导入。

迁移工作、原始副本和 ZIP 位于资料目录旁的`.随手记-迁移`目录，每次操作使用独立编号。新资料中的`迁移记录.json`记录本机备份位置。升级、卸载均不删除这些资料。迁移失败不删除旧版原件，也不自动清除诊断及备份。

## 构建与验证

- `npm run package`：构建 Portable 文件夹。
- `npm run package:installer`：构建当前版本 NSIS 安装器。
- `npm run package:all`：构建两种版本。
- `npm run release`：归档安装器、Portable、源码和 SHA-256 校验清单；交付包不包含个人资料。
- `npm test`：包含存储定位、迁移保护、进程中断恢复、版本备份和原有功能测试。
- `npm run test:installer`：真实安装链路验收。必须在尚无安装版的测试环境运行；脚本会拒绝覆盖已注册的正式安装。脚本使用工作区内的安装目录及隔离用户资料，保护并恢复原桌面与开始菜单入口。

安装验收需要先生成仅供测试的旧包：构建后运行`node scripts/package-installer.mjs --qa`，产生1.7.99测试包；再运行`node scripts/package-installer.mjs`生成1.8.0。测试包不可作为正式发布文件。

当前构建未配置数字签名。尚未使用另一台实体电脑或独立 Windows 虚拟机验收；本机隔离目录不能代替所有 Windows 配置的兼容性测试。原生安装器的鼠标操作与截图检查未完成；按用户要求，后续不使用电脑使用技能。
